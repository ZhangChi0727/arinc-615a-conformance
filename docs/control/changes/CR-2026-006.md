## Source decision and handling

ARINC 615A-3 is the sole active ARINC 615A protocol authority. Its wire-version
field is ASCII `A4`; that field does not identify an ARINC 615A-4 edition.
ARINC 665-5 is a bounded current reference for the registered data-format
objects and is not an equivalent replacement for ARINC 665-3. ARINC 645 remains
an open dependency for CRC, check-value, naming-algorithm and complete-integrity
capabilities. The exact identities and roles are machine controlled in the
source register.

The source PDFs are proprietary local inputs. This repository stores only
identity metadata and applicability conclusions: no PDF, screenshot, long
quotation, extraction, test vector derived from protected text, or local
absolute path may be committed.

## Superseded active assumption

Any active dependency, implementation target or normative-basis assumption for
ARINC 615A-4 is withdrawn. Frozen historical artifacts retain their bytes and
may retain historical wording; the register classifies those paths as
`HISTORICAL-SUPERSEDED`. A future source can become active only after acquisition
and identity registration, applicability delta, change control and independent
review. No future target is pre-registered.

## Technical direction

The minimum sufficient behavioral skeleton is one lightweight observable timed
EFSM. Test and Analysis remain complementary: first-cycle Analysis is bounded to
requirement/obligation traceability, state/transition/timing coverage, robust
timing margin and measurement-error budgets, and mutation/held-out adequacy in
a finite fault domain. DTMC is not protocol semantics; HMM/ML diagnosis and
Bayesian calibration are deferred. FMEA may later prioritize faults but cannot
decide conformance. TTCN-3 is neither a dependency nor a selected platform and
requires a separate ADR/CR before adoption.

This choice preserves an auditable and publishable analysis chain without
introducing models that cannot yet be identified or calibrated because no CRS,
real Configuration or execution population exists.

## Open-source reuse policy

L1 architecture/behavior reference is allowed only with project, version,
license and observed-architecture records. L2 black-box/differential IUT use may
be allowed later with fixed version and license and produces instance-scoped
conclusions. L3 source, constants and test-vector reuse is prohibited until
independent license, source-cleanliness and architecture-fit review. Project
ARIEL is recorded as GPL-2.0; Thomas Vogt's MPL-2.0 implementation is based on
615A-4. Neither is standards authority, and this change copies nothing from
either implementation.

## Layered target architecture

The target dependency direction is protocol profile/source identity/capability
→ protocol-file codecs → injectable `DatagramIO`/`Clock`/`TraceSink` → TFTP
session → ARINC 615A adaptation → Information/Upload/Download/FIND operations →
TP/Case/Procedure/Oracle → Observation/Result/Evidence/Decision/Claim. Layers
must be independently replaceable and testable. Information may bootstrap
engineering but cannot change the formal base claim; Upload remains the first
formal base-VCS operation, followed by Download. Tools may produce controlled
Observation, Result and Evidence but cannot promote claims.

## 来源决定与处理

ARINC 615A-3 是唯一活动的 615A 协议权威。其线协议版本字段为 ASCII `A4`，不能据此
把标准版本写成 615A-4。ARINC 665-5 只是登记数据格式对象的有边界当前参考，不等价替代
665-3。ARINC 645 仍是 CRC、check-value、命名算法和完整完整性能力的开放依赖。精确身份
和角色由来源登记册机器控制。

标准 PDF 是本地专有输入。仓库只保存身份元数据和适用性结论，不得提交 PDF、截图、长
引文、提取物、源自受保护文本的测试向量或本机绝对路径。

## 被取代的活动假设

撤销所有把 615A-4 作为活动依赖、实现目标或规范基础的假设。冻结历史产物保持字节不变，
并可保留历史文字；登记册将其标为 `HISTORICAL-SUPERSEDED`。未来来源只有在取得和登记
身份、完成 applicability delta、变更控制和独立评审后才能激活；当前不预填迁移目标。

## 技术方向

采用单一轻量可观测 timed EFSM。Test 与 Analysis 保持互补；首轮 Analysis 仅覆盖需求/
义务追踪、状态/迁移/时序覆盖、稳健时序裕量与测量误差预算，以及有限故障域中的 mutation/
held-out adequacy。DTMC 不是协议语义；延期 HMM/ML 诊断和 Bayesian calibration。FMEA
以后只能提供故障分类和优先级，不能判定符合性。TTCN-3 不是当前依赖或选定平台，引入时
必须另开 ADR/CR。

这一选择在尚无 CRS、真实 Configuration 和执行总体时避免引入不可识别、不可校准或高维护
成本模型，同时保留可审计、可发表的分析链。

## 开源复用政策

L1 架构/行为参考只有在记录项目、版本、许可证和所观察架构时允许；L2 黑盒/差分 IUT 可
在以后固定版本和许可证后使用，结论保持实例范围；L3 源码、常量和测试向量复用在独立完成
许可证、来源洁净度和架构适配评审前禁止。Project ARIEL 为 GPL-2.0；Thomas Vogt 实现为
MPL-2.0 且基于 615A-4。二者均不是标准权威，本变更不复制其内容。

## 分层目标架构

依赖方向为：协议 Profile/来源身份/能力 → 协议文件 codec → 可注入 `DatagramIO`/`Clock`/
`TraceSink` → TFTP session → 615A adaptation → Information/Upload/Download/FIND 操作 →
TP/Case/Procedure/Oracle → Observation/Result/Evidence/Decision/Claim。各层必须可独立替换和
测试。Information 可用于工程 bootstrap，但不改变正式 base claim；Upload 仍是首个正式
base VCS 操作，随后为 Download。工具不能自行晋级主张。
