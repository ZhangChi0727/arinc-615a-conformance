## What happened

On 2026-11-20 the first confirmatory run was executed at `f5fe943`. All 312 cells were recorded as MISSING: the runner defined a replacement inject wrapper in the script module and called the truth-access guard from there; the guard requires the direct caller to be an evaluator or injector module, so every inject was rejected with `TruthLeakageError`, and a retry of each cell failed the same way. The guard behaved correctly; the defect is in the runner. Unit tests replaced the live path with stubs, so they never covered this guard, and review did not catch it.

## Why this is not post-hoc selection

Every row's verdict, truth parent hypothesis, candidate set and stop class is empty; the analysis file contains no valid contrast. Nobody has seen any confirmatory cell result, so re-running after the fix does not involve result-driven selection.

## Handling

- Archive the first run's raw attempts, analysis file and run log unchanged under `artifacts/confirmatory/void-run-1/`, record SHA-256, and label them as a runner tooling defect that produced no verdicts and is VOID.
- Fix the runner: the inject wrapper no longer calls the guard from the script module; an allowed injector/evaluator module performs the guard, which remains effective.
- Add a real end-to-end test that does not use stubs, using only a unit identical to the published pilot; the pilot result is deterministic and already public, so it does not leak new confirmatory information.
- Registration v2 cells, metrics, contrasts, tests and stopping rules are unchanged; only the hashed runner-script hash is updated, and the run commit becomes this CR's merge commit.

## 发生了什么

2026-11-20 在 `f5fe943` 上执行了首次确认性运行。312 个单元格全部记为 MISSING：运行脚本为注入单元参数而自建的注入包装函数位于脚本模块内，并在其中调用真值访问守卫；守卫要求直接调用者属于评估或注入模块，因此每次注入都以 `TruthLeakageError` 被拒绝，重跑一次后仍失败。守卫行为正确，缺陷在运行脚本。单元测试以替身函数替换了实际运行路径，未覆盖该守卫，审查也未发现。

## 为何不构成事后选择

所有行的判定、真值父假设、候选集、停止类别均为空，分析文件中不存在任何有效对比。没有人看到任何确认性单元格的结果，因此修复后重跑不涉及结果驱动的选择。

## 处理

- 首次运行的原始文件、分析文件与运行日志原样归档于 `artifacts/confirmatory/void-run-1/`，并记录 SHA-256，标注为"运行工具缺陷，未产生任何判定，作废"。
- 修复运行脚本：注入包装函数不再在脚本模块内调用守卫，而是交由允许的注入模块完成，守卫照常生效。
- 新增不使用替身的真实端到端测试，仅使用与试点完全相同的单元；试点结果是确定性的且已公开，不泄露新的确认性信息。
- 登记 v2 的单元格、指标、对比、检验与停止规则不变；只更新被哈希的运行脚本哈希，运行提交改为本 CR 的合并提交。
