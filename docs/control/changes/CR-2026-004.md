# CR-2026-004 — Certification-Oriented Evidence Architecture (v4.3)

| Field | Value |
|---|---|
| Change class | Baseline — evidence architecture and traceability semantics |
| Candidate baseline | RB-2026-001-v4.3 |
| Prior frozen baseline | RB-2026-001-v4.2.1 (remains immutable) |
| Method semantics | Timed-conformance mathematics (equations 1–14, T1–T5) unchanged |
| Status | Candidate; Draft until independent baseline review completes |
| Trigger | Architecture review against recognized aviation development-assurance and authority-review principles |

## Problem

The v4.2/v4.2.1 baseline has strong configuration, traceability, evidence,
timing, and research controls, but it has four structural weaknesses:

1. it lacks a verification-objective layer between requirements and test
   purposes, so a single `PASS` can be read as closing an obligation;
2. execution verdicts and compliance status are insufficiently separated;
3. the single T0–T3 ladder conflates certification-oriented assurance with
   research maturity (mutation adequacy, Bayesian calibration, diagnosis,
   transferability), making research results appear as higher assurance tiers;
4. the Evidence Manifest is execution-level but is treated as the top-level
   compliance artifact.

## Trigger and affected baseline semantics

- assurance tiers (T0–T3 superseded by orthogonal A0–A4 and R0–R5);
- traceability schema (core assurance relations split from research extensions);
- claim/evidence model (domain-specific claims replace C-T0…C-T3);
- evidence manifest role (redefined as Execution Evidence Manifest under a new
  Compliance Evidence Index);
- gate ownership and wording (internal gates are not authority gates);
- research/engineering boundaries;
- reporting architecture.

## Alternatives considered

1. keep current T0–T3 and only rename levels;
2. add an objective layer but keep a single maturity axis;
3. full two-axis assurance restructuring with verification-objective and
   objective-satisfaction layers.

Preferred: Option 3.

## Approved change scope

- introduce Verification Objective as a first-class controlled object;
- introduce Objective Satisfaction Record as a reviewed closure artifact;
- introduce a reviewer-facing Compliance Evidence Index above evidence
  manifests;
- introduce Test Article/Setup/Procedure Conformity records;
- introduce a controlled Problem/Deviation Closure record; treat execution
  validity, case verdict, objective status, and compliance status as distinct
  with no automatic promotion; split T0–T3 into orthogonal A0–A4
  certification-oriented assurance states and R0–R5 research-evidence maturity
  states; separate core assurance traceability from engineering/research
  extensions; add a controlled certification-evidence literature basis and a
  reference catalog; state explicit non-claims; extend the baseline validator.

## Migration

- `RB-2026-001-v4.2.1` remains frozen;
- v4.3 does not retroactively alter previous evidence;
- historical T0–T3 labels are not silently converted to A0–A4;
- existing raw evidence may be referenced by v4.3 only with explicit
  re-evaluation under the new objective and closure contracts;
- timing formulas and robust timing semantics remain unchanged;
- a finite test suite still does not prove all behavior;
- no certification credit is gained by adopting the new architecture.

## Risks

- over-claiming certification relevance;
- documentation complexity and bilingual divergence;
- broken links or identifiers;
- accidental semantic change to timed-conformance rules;
- migration ambiguity;
- Verification Objective duplicating Test Purpose.

## Acceptance criteria

See section 21 of the v4.3 baseline record and the extended baseline validator.

## Review disposition

Pending independent baseline review. This change request becomes effective
only after a reviewed gate approves the v4.3 candidate baseline and the PR is
merged under `CHANGE_CONTROL.md`.

## 问题

v4.2/v4.2.1 基线在配置、追踪、证据、时序和研究控制方面较强，但存在四个结构性弱点：缺少验证目标层导致单个 `PASS` 可被误读为关闭义务；执行判定与合规状态未充分分离；T0–T3 单轴将面向认证的保证与研究成熟度混为一谈；证据清单属执行级却被当作顶层合规产物。

## 触发与受影响基线语义

保证层级（T0–T3 由正交的 A0–A4 与 R0–R5 替代）、追踪 schema（核心保证关系与研究扩展分离）、主张/证据模型、证据清单角色（重定义为执行证据清单并置于新的合规证据索引之下）、门禁措辞、研究/工程边界与报告架构。

## 备选方案

1. 保留 T0–T3 仅改名；
2. 增加目标层但保留单成熟度轴；
3. 引入验证目标与目标满足层的完整两轴保证重构。

首选：方案 3。

## 已批准变更范围

引入验证目标、目标满足记录、面向审查的合规证据索引、测试件/装置/规程符合性记录和问题/偏差关闭记录；将执行有效性、用例判定、目标状态与合规状态分离且禁止自动晋级；将 T0–T3 拆分为正交的 A0–A4 面向认证保证状态与 R0–R5 研究证据成熟度状态；分离核心保证追踪与工程/研究扩展；新增受控的认证证据文献基础与参考目录；声明明确非主张；扩展基线校验器。

## 迁移

RB-2026-001-v4.2.1 保持冻结；v4.3 不回溯修改既有证据；历史 T0–T3 标签不静默转换为 A0–A4；既有原始证据仅在新的目标与关闭契约下显式重评后才可被 v4.3 引用；时序公式与稳健时序语义不变；有限测试套件仍不足以证明全部行为；采用新架构不获得任何认证信用。

## 风险

过度声索认证相关性；文档复杂度与双文分歧；链接或标识破坏；时序符合性规则意外改变；迁移歧义；验证目标与测试目的重复。

## 接受准则

见 v4.3 基线记录第 21 节及扩展后的基线校验器。

## 评审处置

待独立基线评审。本变更请求仅在受评审门禁批准 v4.3 候选基线且 PR 按 `CHANGE_CONTROL.md` 合并后生效。
