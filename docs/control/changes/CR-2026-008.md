## Decision and boundaries

M1 remains the immutable CRS input. M2 is the model and refinement authority.
Compliant Network is retained. AFDX, P3 profiled deviations, FIND, DOWNLOAD,
media-set services and integrity algorithms stay out of this candidate.
No codec, executable engine, TP/VC, Project Configuration or conformance claim
is authorized.

## Scope

UPLOAD is the first formal base VCS direction. INFORMATION is modeled for
bootstrap and the supporting operation already in the M1 profile. Observation
separates Data Loader and Target Hardware inputs/outputs. Local evaluation is
not claimed as network-visible.

## Model and trace

The machine is M=(S,s0,V,C,P,E,T,Inv). Every M1 requirement has a disposition
and a trace to a state, transition, field/status/object constraint, clock,
interface or scope object. UPLOAD models the list-ready, LUR request/ACK/list
transfer and subsequent file stages as distinct. Timing uses restricted ASTs
with clock-enabled timeouts; Attachment 4 keeps the source retry terms.
Unresolved bounds are NOT-CHECKED. Input acceptance is fail-closed against git
objects.

DATA-LOADER WRQ / TARGET-HARDWARE ACK / DATA-LOADER DATA). That

## Acceptance criteria

source, or missing timing core semantics cannot be deferred. This CR does not

Head, user authorization, ordinary two-parent merge with that Head as second
parent, and successful main CI. Linear-history policy remains a user decision
at merge time. M3 stays blocked by EXECUTABLE-FOUNDATION-GATE.
