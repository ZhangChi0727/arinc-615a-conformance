## Problem

The first eight PR #9 commits proposed useful ARINC evidence objects and
taxonomies before an external GVS authority boundary existed. Leaving the
proposal unchanged would risk presenting local Profile/Binding/project content
as Generic method architecture and would conflate migration preparation with
method compatibility or exercised instance evaluation. The correction must:

1. bind one immutable external Candidate GVS Core definition;
2. separate Core, Profile, ARINC Product Binding, and Project Configuration;
3. preserve valuable VO/OSR/CEI and evidence controls as local candidates;
4. keep compatibility `NOT-DETERMINED` and evaluation `NOT-EXERCISED`;
5. preserve the frozen v4.2.1 baseline and the eight-commit proposal history.

## Trigger and affected baseline semantics

- external method identity and cross-repository contract;
- authority and dependency boundaries for Core/Profile/Binding/Configuration;
- local object, evidence, traceability, gate, and lifecycle semantics;
- Profile/Binding classification of L0–L7, A0–A4, R0–R5, RG, and G;
- instance finding, rollback, later evaluation, and third-handshake routes;
- research, engineering, reporting, and validation surfaces.

## Alternatives considered

1. leave the pre-framework proposal unchanged;
2. copy or recreate a Generic Core inside the ARINC repository;
3. bind the immutable external Core and reclassify local objects without
   rewriting the eight historical commits.

Preferred: Option 3. It preserves history and useful work while maintaining a
single generic-method authority.

## Approved change scope

- create immutable external binding `TMP-XRB-ARINC615A-01`;
- establish Profile `TMP-CTP-ARINC615A-01`, Product Binding
  `TMP-PB-ARINC615A-01`, and not-yet-established Project Configuration
  `TMP-PC-ARINC615A-01` boundaries;
- migrate VO, OSR, CEI, Evidence Manifest, Test Conformity, Problem Closure,
  traceability, claims, gates, and lifecycle states as local candidate objects;
- retain non-automatic promotion and explicit non-claims;
- prepare, but do not execute, the external instance evaluation protocol;
- extend governance validation and produce an independent-review handoff.

## Pre-framework proposal provenance

PR #9 head `53a98447bcfa862f082ce443d69115067d3ff2f1` recorded the
pre-framework L0–L7, A/R, VO, OSR, and CEI proposal. Method PR #14 later merged
at `48dd8232b7efe6b0dba3fcb75dfc154d034d2b0b`. Five ordinary correction
commits reclassify the proposal without amend, rebase, squash, force-push, or a
claim that the original proposal was framework-based. v4.2.1 remains the active
frozen legacy baseline; v4.3 gains no active semantic authority before review
and merge.

## Migration

- `RB-2026-001-v4.2.1` remains frozen;
- v4.3 does not retroactively alter previous evidence;
- historical T0–T3 labels are not silently converted to A0–A4;
- existing raw evidence may be referenced by v4.3 only with explicit
  re-evaluation under the new objective and closure contracts;
- timing formulas and robust timing semantics remain unchanged;
- a finite test suite still does not prove all behavior;
- no certification credit is gained by adopting the new architecture.
- compatibility remains `NOT-DETERMINED` and evaluation remains
  `NOT-EXERCISED`;
- L0–L7, A/R, RG, and G remain ARINC/Profile/project candidate semantics.

## Risks

- over-claiming certification relevance;
- documentation complexity and bilingual divergence;
- broken links or identifiers;
- accidental semantic change to timed-conformance rules;
- migration ambiguity;
- Verification Objective duplicating Test Purpose.

## Acceptance criteria

See section 21 of the v4.3 baseline record and the extended baseline validator.

## Review disposition

Pending independent baseline review. This change request becomes effective
only after a reviewed gate approves the v4.3 candidate baseline and the PR is
merged under `CHANGE_CONTROL.md`.

## 问题

PR #9 前八笔提交在外部 GVS 权威边界建立前提出了有价值的 ARINC 证据对象和 taxonomy。
若原样保留，会把本地 Profile/Binding/项目内容误写为 Generic 方法架构，并把迁移准备与方法
兼容性或已执行实例评价混淆。此次修订必须固定绑定唯一外部 Candidate GVS Core，分离四层
所有权，保留本地对象价值，使兼容性为 `NOT-DETERMINED`、评价为 `NOT-EXERCISED`，并保存
v4.2.1 和八笔提案提交的真实历史。

## 触发与受影响基线语义

受影响内容包括外部方法身份、Core/Profile/Binding/Configuration 权威边界、本地对象与证据
追踪/门禁/生命周期语义、L0–L7/A/R/RG/G 的 Profile 归类、finding/回滚/后续评价/第三次握手
路线，以及研究、工程、报告和校验界面。

## 备选方案

1. 原样保留 pre-framework 提案；
2. 在 ARINC 仓库复制或重建 Generic Core；
3. 绑定不可变外部 Core，在不改写八笔历史提交的前提下重新归类本地对象。

首选方案 3：既保留历史和有价值工作，又维持唯一通用方法权威。

## 已批准变更范围

建立 `TMP-XRB-ARINC615A-01` 不可变外部绑定，建立 Profile
`TMP-CTP-ARINC615A-01`、Product Binding `TMP-PB-ARINC615A-01` 和尚未建立的
Project Configuration `TMP-PC-ARINC615A-01` 边界；迁移 VO、OSR、CEI、Evidence
Manifest、Test Conformity、Problem Closure、追踪、主张、门和生命周期状态为本地候选；
保持非自动晋级和显式非主张；准备但不执行外部实例评价协议；扩展治理校验并形成独立评审交接。

## 前框架提案来源

PR #9 head `53a98447bcfa862f082ce443d69115067d3ff2f1` 记录了 pre-framework 的
L0–L7、A/R、VO、OSR 和 CEI 提案。方法 PR #14 后来以
