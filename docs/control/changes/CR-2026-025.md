## Objective and controlled scope

Authorize one adapter that runs CL-T, CL-A, CL-TA and CL-LOOP on the Phase A
simulated IUT using the registered scene pool, action library, stop classes and
T5 oracle, with exclusive resource mode per run. Arms never see fault plans,
evaluator truth, or other-arm records. CL-LOOP constructs existing
`cltav_runtime.session.ReferenceSession`. Label SIMULATED-IUT. No manuscript
result cell is filled. Phase C/D remain out of scope.

## Authorized deliverables

- RR-PR28-2026-004 M1: drop `state` from algorithm-visible records.
- RR-PR28-2026-004 M2: `evaluator_fault_record` in the evaluator package, gated
  by the truth capability / fail-closed guard.
- Shared action library and fair-cost table for TEST/ANALYSIS/Prep/Recover.
- Four arms behind `a615a_sim.algorithm.adapter.run_arm`.
- Evaluator harness that confirms injection, resets, overlays, then isolates
  per-arm ledgers.

## Boundaries and non-authorizations

- Does not change `src/cltav_runtime/` semantics, CRS, M2, or algorithm
  interfaces.
- Does not close DEC-IUT, DEC-TRUTH, DEC-CLOCK, DEC-EQUIV, DEC-SAMPLE, or
  DEC-RESOURCE.
- Does not fill PH-RES-* / PH-ABS-RESULT / PH-STAT-N or claim superiority.
- Does not start Phase C/D, Ready, merge, tags, or protection changes.

## Acceptance

| ID | Condition |
|---|---|
| AC-01 | Algorithm-visible records omit internal `state`. |
| AC-02 | Arm frames cannot call `evaluator_fault_record`; missing capability fails closed. |
| AC-03 | CL-T issues only the predetermined TEST sequence and charges acquisition for executed tests. |
| AC-04 | CL-A issues only ANALYSIS, charges computation, and invents no acquisition. |
| AC-05 | CL-TA collects with the frozen TEST sequence then analyses; no TEST after analysis. |
| AC-06 | CL-LOOP constructs `ReferenceSession`. |
| AC-07 | Other arms do not receive CL-LOOP observation logs. |
| AC-08 | All four arms run on the same (scene, fault) after reset and overlay. |
| AC-09 | The versioned pilot hypothesis model in `configs/research/cltav_pilot_hypothesis_model_v1.json` encodes `h_normal` plus the five `H_single` faults with per-action observables, presence and measurement ticks derived only from public catalogue fields. `(LATE, ABSENT)` remain two hypotheses; DEC-EQUIV stays OPEN. |
| AC-10 | Every arm ends with a candidate hypothesis set and a stop class computed only from that arm's visible records. CL-A, CL-TA and CL-LOOP share the same model and consistency filter; CL-T reports the observation-implied candidate set without ANALYSIS credit. Frozen arms that finish their sequence use `Stop-Singleton` on a singleton set, otherwise `Stop-NoDistinguisher`; unaffordable actions use `Stop-Budget`. Stop-class names are only those already registered in the design JSON / adapter library. |
| AC-11 | Confirmation traces never reach algorithm-visible records. Arm modules never access `AlgorithmVisibleTarget._target`. ## DM rulings recorded (RR-PR28-2026-005)

1. Evaluator confirm → reset → overlay is accepted; confirmation traces are excluded from algorithm-visible records.
2. Frozen-arm terminal mapping: singleton → registered identification stop (`Stop-Singleton`); otherwise `Stop-NoDistinguisher`; unaffordable → `Stop-Budget`.
3. Experiment hypothesis model is an experiment-side authority, versioned under `configs/research/`, recorded as a pilot artefact. DEC-EQUIV remains OPEN.
4. ANALYSIS charging follows the fairness table.
5. TEST-ABORT is not on the predetermined path; SC-ABORT ABORT is IUT trajectory.

## 验收

## 已记录的 DM 裁决（RR-PR28-2026-005）

1. 评价者确认→复位→叠加获接受；确认痕迹不得进入算法可见记录。
2. 冻结臂终端映射：单例→已登记识别停止类（`Stop-Singleton`）；否则 `Stop-NoDistinguisher`；不可负担→`Stop-Budget`。
3. 实验假设模型为实验侧权威，版本化登记于 `configs/research/`，作为试点制品记录。DEC-EQUIV 保持 OPEN。
4. ANALYSIS 计费按公平表。
5. TEST-ABORT 不在预定路径上；SC-ABORT 的 ABORT 来自 IUT 轨迹。
