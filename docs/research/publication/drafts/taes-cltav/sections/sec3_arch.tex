\section{System Engineering and Verification Architecture}
\label{sec:arch}

Protocol CRS, tool requirements and experiment requirements stay in separate
layers. Row count does not prove a method. A concrete owned trace is source
unit \texttt{SU-ARINC-615A-3-SECTION-6-3-2-}\allowbreak
\texttt{SEQUENCE-CHART-A-E007-7726A816FFE7}
\(\to\) CRS-M1-00365/00366/00367 \(\to\) LUR write-order constraint \(\to\)
planned Test/Analysis verification case \(\to\) later tool module. The IDs are
real bound-M1 identifiers. \texttt{satisfy}/\texttt{verify} in the SysML view
are model relations, not executed verification. No standard figure is reprinted.

The layering responds to two aviation lessons without importing their authority.
F-LAS shows the usefulness of explicit requirements-to-procedure traceability
for loading identity, integrity, interrupted loading and version conflict, but
its procedures were proposed rather than executed~\cite{marques2021}. Avionics
MBT also makes configuration, model preparation, simulator and oracle boundaries
part of the test problem~\cite{efkemann2011,sartaj2021}. Accordingly, the CRS
constrains legal protocol evidence, the tool realizes method contracts, and the
evaluator owns independent truth; none can silently stand in for another.

Two machines must not be merged. \(M_{\mathrm{sess}}\) selects from
\(S\subseteq A(q)\), charges once, updates \(H\) and returns a named stop.
\(M_{\mathrm{prot}}\) is the UPLOAD/INFORMATION black box. Execute issues a
stimulus and obtains a raw execution record. Interpretation, not the network
port, produces the compatible class \(I_z\) and hypothesis survivors.

Expanded CRS leaves do not add FIND or DOWNLOAD transitions to
\(M_{\mathrm{prot}}\).
The development contract now binds eight algorithm interfaces and seven
experiment interfaces to typed inputs, outputs, ownership, failure, resource,
acceptance, and successor implementation locations.  The first slice also
preserves six CRC-bearing protocol obligations and their ARINC~645 parameter
leaves.  The six contracts remain distinct: INFORMATION and UPLOAD receiver
support, final-image/LSP check value, optional old/new-file comparison,
equal CRC values for two distinct files sharing one part number, and
status-file continuation after the final DATA
while integrity calculation remains in progress.  This closes their
specification dependency only: the runtime
integrity capability remains \emph{not established} until implementation,
project configuration, controlled-vector execution, and an independent gate
record exist.  Missing evidence therefore yields \texttt{NOT-EVALUATED}, not a
protocol verdict.
