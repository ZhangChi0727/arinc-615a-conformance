## Reason

The frozen registration requires a run at the registration merge commit, but the
repository had only the pilot runner and no runner that reads the confirmatory
design. This CR adds scripts only. It does not add, remove, or redefine any
cell, metric, contrast, test, or stopping rule.

## Content

- `scripts/run_cltav_confirmatory.py`: pre-flight refuses a dirty worktree or a
  mismatch among the three registration config hashes; then runs each of the 312
  design cells once; writes `artifacts/confirmatory/` with commit SHA and config
  hashes on every row.
- `scripts/analyze_cltav_confirmatory.py`: read-only over the run results;
  computes M-DETECT, M-LOCALISE, secondary metrics, exact two-sided McNemar, and
  Holm correction as registered.
- The registration's "exact 95% confidence interval for the paired difference"
  is implemented as: report discordant-pair counts b, c, the paired-difference
  point estimate (b−c)/n, and the Clopper–Pearson exact interval for b/(b+c).
  This is an implementation-level reading and requires review confirmation.
- The run commit becomes this CR's merge commit; relative to the registration
  base that commit only adds the scripts and their tests.
- Tests use only synthetic data and a dry run (enumerate cells, check hashes).
  No real cell is executed, so no interim look is formed.

## 内容

- `scripts/run_cltav_confirmatory.py`：运行前校验工作树干净、登记中三个配置哈希一致，否则拒绝运行；按设计逐格运行 312 个单元格各一次；结果写入 `artifacts/confirmatory/`，每行记录提交 SHA 与配置哈希。
- `scripts/analyze_cltav_confirmatory.py`：只读运行结果，按登记计算 M-DETECT、M-LOCALISE、次指标、精确双侧 McNemar 与 Holm 校正。
- 登记中"配对差的精确 95% 置信区间"按以下方式实现：报告不一致配对数 b、c，配对差点估计 (b−c)/n，以及 b/(b+c) 的 Clopper–Pearson 精确区间。此为实现层面的解释，须经审查确认。
- 运行提交改为本 CR 合并提交；该提交相对登记基点只新增上述脚本与其测试。
- 测试只用合成数据和空跑（列举单元格、校验哈希），不运行任何真实单元格，避免形成中期查看。
