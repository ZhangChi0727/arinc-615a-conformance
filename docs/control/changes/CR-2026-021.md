## Objective and controlled scope

Authorize a bounded reference implementation of the existing CL-TAV session
coordination and an in-process synthetic engineering environment.  The narrow
delivery path is:

`verified authority snapshots → finite prediction/admission/snapshot → one charged synthetic action → visible record interpretation → versioned history update → next round or named stop`.

The runtime consumes fixed Git-object bytes of the development package and
interface registry, records their commit/path/SHA-256 identities, and exposes a
typed projection only.  It does not copy or replace their authority.  A first
engineering checkpoint must run at least two feedback rounds: the second round
consumes the first round's committed history and confirmed summary.  Synthetic
state, faults and evaluator truth stay outside the algorithm API; an execution
record is not a protocol verdict or an experiment result.

## Authorized deliverables

- A separate `cltav_runtime` package with verified source bindings, closed
  session/history/snapshot values, finite prediction, admission, execution,
  interpretation, history and stop adapters.
- A deterministic, finite, process-local synthetic environment that accepts an
  admitted action and returns only visible execution evidence.  It must not
  receive the hypothesis set, selection score, evaluator truth or an expected
  answer.
- Controlled synthetic fixtures, a production entry point, structured runtime
  evidence and tests for two-round feedback, conservative ERROR/UNKNOWN paths,
  source identity, resource accounting and truth separation.
- An implementation mapping and installation evidence that identify inputs,
  limits, output records and still-open dependencies.

## Boundaries and non-authorizations

- This CR implements only a finite reference projection of the already
  controlled method and interfaces.  It does not alter CRS, M2, method,
  algorithm, interface-registry authority, experiment definitions, statistical
  design, baseline or tag.
- It does not authorize network activity, an IUT, packet injection, a general
  timed-EFSM solver, full offline diagnosis, CRC/integrity establishment,
  Project Configuration, M3 activation, capability/conformance/certification
  claims, confirmatory experiment execution, result publication, Ready,
  approval, merge or submission.
- All B/C runs are labelled `SYNTHETIC-ENGINEERING-VALIDATION`.  Synthetic
  truth is evaluator-only and does not become independent experimental truth.
- Researcher contract and manuscript review remains pending until an independent
  Researcher result is delivered.  Engineering work must report a real
  cross-domain conflict to the Decision Maker rather than selecting a
  convenient interpretation.

## 目标和受控范围

授权对既有 CL-TAV 会话协调和进程内合成工程环境进行有界的参考实现。窄交付路径为：

`经核验的权威快照 → 有限预测／准入／快照 → 一次已计费的合成动作 → 可见记录解释 → 带版本历史更新 → 下一轮或具名停止`。

运行时消费开发包和接口登记的固定 Git 对象字节，记录其 commit／path／SHA-256 身份，
只暴露类型化投影；不复制或取代其权威。首个工程检查点至少运行两轮反馈：第二轮必须
消费第一轮已提交的历史和已确认摘要。合成状态、故障和评价真值留在算法 API 之外；执行
记录不是协议判定，也不是实验结果。

## 授权交付物

- 独立的 `cltav_runtime` 包，包括经核验的来源绑定、封闭的会话／历史／快照值、有限的
  预测、准入、执行、解释、历史和停止适配器。
- 确定性的有限进程内合成环境：仅接受已准入动作并返回可见执行证据；不得接收假设集、
  选择评分、评价真值或预期答案。
- 受控合成 fixture、生产入口、结构化运行证据，以及两轮反馈、保守 ERROR／UNKNOWN
  路径、来源身份、资源记账与真值隔离测试。
- 标识输入、限额、输出记录和待关闭依赖的实现映射及安装证据。

## 边界和未授权事项

- 本 CR 仅实现已受控方法和接口的有限参考投影；不改变 CRS、M2、方法、算法、接口登记
  权威、实验定义、统计设计、baseline 或 tag。
- 不授权网络活动、IUT、报文注入、通用 timed-EFSM 求解器、完整离线诊断、CRC／完整性
  建立、Project Configuration、M3 激活、能力／符合性／认证主张、确认性实验执行、结果
  发布、Ready、批准、合并或投稿。
- 所有 B/C 运行均标为 `SYNTHETIC-ENGINEERING-VALIDATION`。合成真值只属于评价端，
  不成为独立实验真值。
- 在独立 Researcher 结论交付前，研究合同和论文核对仍为 pending。工程实现发现真实跨域
  冲突时必须交 Decision Maker 裁定，不得选择对实现方便的解释。
