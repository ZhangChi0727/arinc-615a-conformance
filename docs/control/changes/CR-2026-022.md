## Objective and controlled scope

Authorize a bounded, process-local engineering prototype for the beginning of a
615A UPLOAD control slice. The controlled object is a resettable DATA-LOADER
software surrogate with a TARGET-HARDWARE driver. The narrow fragment starts
after a named list-submission preparation boundary and covers the distinct
ready, accepted, WRQ, ACK and DATA semantics bound to `CRS-M1-00364` through
`CRS-M1-00367` and their M2 anchors.

The eventual prototype must provide NORMAL, EARLY-WRQ and EARLY-DATA object
variants; deterministic virtual time; visible ordered journal evidence;
evaluator-only injection and truth records; and a narrow CL-LOOP engineering
integration. It must retain explicit source identities, reset, resource,
history, confirmation and finite-observation boundaries. A finite no-WRQ
inspection is a completed engineering log check, not a protocol no-response
verdict or a fabricated protocol response.

## Authorized deliverables

- One closed scenario package and schema that bind exact authority snapshots,
  the limited UPLOAD source relations, role/direction semantics, the finite
  hypothesis domain, actions, observations, lifecycle and non-evaluated
  obligations.
- A small, independent loader surrogate and TH driver, with actual guard/
  emission differences for the two single-fault variants, full reset and
  installation/read-back/activation records.
- A bounded adapter to the existing reference-session contracts, retaining the
  existing ownership of selection, snapshot, interpretation and history
  commitment. The object must not receive hypotheses, predictions, scores,
  evaluator truth or expected answers.
- Engineering-only `run`, `verify` and `replay` evidence production, including
  transactional publication and non-editable-wheel installation checks, if and
  only if the preceding fixed-head stages are independently accepted.
- Minimal engineering-state synchronization and research-reader boundary notes
  that describe facts actually established by this increment only.

## Boundaries and non-authorizations

- This CR does not amend CRS, M2, controlled source registrations, accepted
  method/algorithm semantics, experiment definitions, arm fairness, statistical
  accounting, the offline capture pipeline, or the existing runtime's accepted
  semantics.
- It does not authorize a complete UPLOAD operation, LUR bytes/checksums/CRC,
  real networking, packet injection, a real IUT, SIL/HIL, a general solver,
  root-cause finding, protocol conformance, physical-clock characterization,
  four-arm execution, pre-experiment/confirmatory results, or independent
  mathematical approval.
- It does not establish any `NOT-ESTABLISHED` integrity capability, Project
  Configuration, M3, baseline, tag, release, certification, or scientific
  claim. The experimental-design admission remains blocked.
- A reset is not a protocol abort; an engineering object fault is not a real
  device fault; evaluator truth is not independent experimental truth.
- The PR remains Draft. This CR authorizes neither Ready for review, GitHub
  approval, merge nor publication.

## 目标和受控范围

本 CR 授权实现 615A UPLOAD 控制片段起始部分的有界、进程内工程原型。受控对象是可复位的
DATA-LOADER 软件替身及 TARGET-HARDWARE 驱动。狭窄片段从具名的列表提交准备边界之后开始，
覆盖 `CRS-M1-00364` 至 `CRS-M1-00367` 及其 M2 锚点所约束的就绪、接受、WRQ、ACK 与 DATA
的彼此区分。

最终原型必须提供 NORMAL、EARLY-WRQ 与 EARLY-DATA 对象变体、确定性虚拟时基、可见的有序
journal 证据、仅属于评价端的注入和真值记录，以及狭窄的 CL-LOOP 工程接入。它必须保留明确的
来源身份、复位、资源、历史、确认和有限观察边界。有限的“没有 WRQ”检查是完成的工程日志检查，
不是协议无响应判定，也不是伪造的协议响应。

## 授权交付物

- 一份封闭的场景包和 schema，绑定精确权威快照、有限 UPLOAD 来源关系、角色／方向语义、
  有限假设域、动作、观测、生命周期及未评价义务。
- 小型且独立的 loader 替身和 TH 驱动；两个单故障变体必须真实改变 guard／事件发射分支，
  并带有完整复位和安装／读回／激活记录。
- 对既有 reference-session 合同的有界适配，保留选择、快照、解释和历史提交的既有职责。
  对象不得接收假设、预测、评分、评价者真值或预期答案。
- 仅在此前固定 Head 阶段被独立接受时，提供工程 `run`、`verify`、`replay` 证据生产、事务式
  发布和 non-editable wheel 安装检查。
- 只同步本增量实际建立的工程事实及研究读者边界。

## 边界和未授权事项
