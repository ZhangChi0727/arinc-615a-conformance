## Objective and scope

Authorize one bounded, offline, read-only implementation increment for the
accepted first UPLOAD/INFORMATION development slice.  It delivers a
reproducible intake pipeline:

`capture file → packet record → IPv4 datagram reconstruction → UDP/TFTP transfer reconstruction → bounded protocol event → traceable evidence index`.

The implementation consumes only the current controlled CRS/model/contracts and
the existing exploratory-capture manifest.  It preserves input identity,
uncertainty, source references, parser/reconstruction diagnostics, and the
distinction between intake evidence and protocol verdicts.

## Authorized deliverables

- A separate `cltav_offline` package and installed command-line entry point for
  synthetic and caller-supplied capture inputs.
- Streaming pcap/pcapng container intake; finite IPv4, UDP and TFTP
  reconstruction; bounded first-slice event extraction; and a versioned JSON
  evidence index with transactional publication.
- Public synthetic fixtures and production-entry tests, plus a read-only,
  manifest-audited exploratory run over the local 23-file corpus without
  committing payloads, absolute local paths, topology, root-cause labels or
  experimental conclusions.
- Implementation-to-contract mapping, run instructions and an acceptance
  report that separately identifies supported parsing behaviour, controlled
  unknowns and later dependencies.

## Boundaries and non-authorizations

- CR-2026-016 remains the historical specification-only authorization.  This
  successor permits only the runtime intake slice described here; it does not
  amend the earlier CR's acceptance meaning.
- No active network I/O, IUT execution, packet injection, full CL-TAV loop,
  ownership oracle, T5 verdict, history update, general solver, M3 activation,
  Project Configuration, runtime-integrity establishment, confirmation
  experiment, capability promotion, certification claim, baseline or tag is
  created.
- A parser/reconstruction status, an annotation or a successfully emitted
  evidence index is not a conformance PASS/FAIL, a product root-cause finding,
  an independent validation result or experimental truth.
- The external historical corpus remains `EXPLORATORY-DEVELOPMENT-ONLY`.  Its
  files are read-only caller inputs, not Git artifacts or a validation set.

## Acceptance

| ID | Condition |
|---|---|
| AC-01 | The implementation begins from the stated common base in an isolated worktree, and the primary user worktree is not switched, reset, cleaned or committed. |
| AC-02 | Capture identity, container diagnostics, timestamp provenance and missing metadata are preserved without inferred topology, clock accuracy, version or root cause. |
| AC-03 | IPv4 reconstruction reports `COMPLETE`, `GAPPED` or `CONFLICT`; duplicate fragments do not duplicate output and conflicting bytes never overwrite earlier evidence. |
| AC-04 | TFTP reconstruction validates request, option, OACK, ACK, DATA and ERROR layouts; identifies the service TID; represents accepted/defaulted/unknown options separately; and does not publish incomplete or conflicting files as complete. |
| AC-05 | Output preserves the packet-to-datagram-to-transfer-to-event source chain, is deterministic under a declared configuration, and is published transactionally. |
| AC-06 | Synthetic production-entry tests exercise normal, controlled-unknown and fatal paths.  CI does not depend on the private corpus or any network execution. |
| AC-07 | The exploratory corpus identity audit and per-file run are recorded without payload, absolute local path, capture annotation promotion or a confirmation claim. |
| AC-08 | Repository gates and final independent review bind the final unchanged Head.  The PR remains Draft until that review accepts it. |

## Evidence and follow-on boundary

This increment can provide engineering evidence about parser behaviour,
reconstruction provenance and declared support boundaries.  It cannot close
runtime integrity, establish a controlled execution environment, or support a
conformance/certification claim.  Later active execution, ownership,
observation, history and experimental increments require their own CR/DD,
evidence and review.

## 目标与范围

授权已接受首轮 UPLOAD／INFORMATION 开发切片的一项有限、离线、只读实现增量。它交付可复现的接入管线：

`捕获文件 → 数据包记录 → IPv4 数据报重建 → UDP/TFTP 传输重建 → 有界协议事件 → 可追踪证据索引`。

实现只消费当前受控的 CRS／模型／合同和现有探索性捕获清单；保留输入身份、不确定性、来源引用、解析／重建诊断，以及接入证据与协议判定之间的边界。

## 授权交付物

- 独立的 `cltav_offline` 包和安装后的命令行入口，用于合成输入与调用方提供的捕获输入。
- 流式 pcap／pcapng 容器接入、有限 IPv4／UDP／TFTP 重建、有界首轮事件提取，以及支持事务发布的版本化 JSON 证据索引。
- 公开合成夹具和生产入口测试；对本地 23 份语料执行只读、清单审计后的探索运行，不提交载荷、绝对本地路径、拓扑、根因标签或实验结论。
- 实现到合同的映射、运行说明和验收报告，分别说明已支持的解析行为、受控未知与后继依赖。

## 边界与非授权项

- CR-2026-016 继续作为仅规格的历史授权。本后继项只许可此处说明的运行时接入切片，不改变前一 CR 的接受含义。
- 不创建主动网络 I/O、IUT 执行、报文注入、完整 CL-TAV 闭环、所有权 oracle、T5 判定、历史更新、通用求解器、M3 激活、Project Configuration、运行完整性建立、确认性实验、能力晋级、认证主张、baseline 或 tag。
- 解析／重建状态、文件注释或成功写出的证据索引都不是符合性 PASS/FAIL、产品根因 finding、独立验证结果或实验真值。
- 外部历史语料继续是 `EXPLORATORY-DEVELOPMENT-ONLY`。文件是调用方的只读输入，不是 Git 制品或验证集。
