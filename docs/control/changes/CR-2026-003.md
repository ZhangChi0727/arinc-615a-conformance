## Trigger and problem

Reader-facing material, developer controls, historical records, and generated
artifacts were distributed across the root and several directory README files.
The structure did not provide one obvious reader update, and repository
navigation was coupled to directory-local prose.

## Approved change scope

- make the root `README.md` the only reader-facing root document;
- place every reader-facing report, tutorial, release, and evidence package
  below `artifacts/`;
- define one control entry for project, research, engineering, and tutorial
  work while preserving atomic records;
- require one self-contained reader report for each reader-facing update and a
  direct link to the current report from the root README;
- relocate existing records without changing RR-2026-001 equations, formal
  semantics, assurance tiers, or claim-release rules;
- retain local research inputs under ignored `local-references/`.

## Impact and migration

All Markdown links and the repository validator must be updated atomically.
The v4.2 release remains an immutable methodological predecessor. The v4.2.1
release changed information architecture and governance references only.
Historical paths are not normative interfaces; controlled artifact IDs and Git
history preserve provenance.

The reviewed PR #6 head and merge commit remain the immutable provenance for
released v4.2 semantics. Administrative status updates, relocations, and
relative-link repairs in this v4.2.1 package do not create new v4.2 method
semantics and must not be used to relabel existing evidence.

## Acceptance criteria

- no root Markdown file exists other than `README.md`;
- no subdirectory `README.md` exists;
- the current reader report is a single bilingual file below
  `artifacts/reports/current/` and is directly linked by the root README;
- each product line has exactly one named control entry;
- local links, bilingual structural checks, tests, and repository validation
  pass;
- an independent reviewer records the release decision before v4.2.1 is called
  frozen.

## 触发因素与问题

面向读者的材料、开发者控制、历史记录和生成产物此前分散在根目录及多个目录 README 中。
原结构没有单一清晰的读者更新入口，仓库导航也依赖目录局部说明。

## 已批准的变更范围

- 根目录只以 `README.md` 作为面向读者的文档；
- 所有面向读者的报告、教程、发布包和证据包均置于 `artifacts/`；
- 项目、研究、工程和教程各定义一个控制入口，同时保留原子记录；
- 每次面向读者的更新形成一份自包含报告，并由根 README 直接链接当前报告；
- 迁移现有记录，但不修改 RR-2026-001 的公式、形式语义、保证层级或主张发布规则；
- 本地研究输入继续置于被忽略的 `local-references/`。

## 影响与迁移

全部 Markdown 链接和仓库校验器必须原子更新。v4.2 仍是不可变的方法论前序发布；v4.2.1
发布只调整信息架构和治理引用。历史路径不是规范接口，受控产物 ID 与 Git 历史保留来源。

PR #6 已评审 head 与合并提交仍是已发布 v4.2 语义的不可变来源。本 v4.2.1 包中的
管理状态更新、路径迁移和相对链接修复不会产生新的 v4.2 方法语义，也不得用于重标既有证据。

## 接受准则

- 根目录除 `README.md` 外不存在 Markdown 文件；
- 子目录不存在 `README.md`；
- 当前读者报告是 `artifacts/reports/current/` 下的一份双语文件，并由根 README 直接链接；
- 每条产品支线恰有一个具名控制入口；
- 本地链接、中英文结构检查、测试和仓库校验全部通过；
- 独立评审者记录发布决定后，v4.2.1 才可称为冻结。
