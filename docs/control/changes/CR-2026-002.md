## Trigger and problem

The repository already separates source code, research control, publication,
and tutorials physically, but three ambiguities remain: `docs/study/` mixes the
meaning of authoritative method and learning material; W7 assigns that path to
the tutorial workstream; and publication/tutorial ownership is combined even
though their evidence responsibilities and release lifecycles differ. Folder
separation alone does not prevent research prose from depending on engineering
internals or tutorials from becoming an accidental normative source.

## Decision

The following paths record the v4.2 realization at approval time. CR-2026-003
later relocates them while preserving the product-domain dependency rules.

- Move the authoritative report and index to `docs/methodology/`.
- Treat methodology research/publication, engineering implementation, and
  verification tutorials as distinct product domains.
- Keep governance and controlled requirements as the shared contract layer.
- Separate publication from tutorial ownership and split tutorials into
  `tutorial/common/` and `tutorial/arinc615a/`.
- Require each cross-domain dependency to identify upstream artifact IDs,
  versions, and applicable gate records.
- Permit feedback from downstream evidence only through CR/DD and Review
  control; do not create direct reverse dependencies on mutable artifacts.

## Interface and traceability contract

Methodology exports terminology, model/trace semantics, verdict rules, evidence
schemas, and gate criteria. Engineering imports those contracts and exports
versioned tool/configuration/environment metadata plus immutable evidence
manifests. Research and publication consume the manifests and export registered
analyses and gate-bounded claims. Tutorials consume a named baseline and, when
executable, a named tool release and stable example/evidence IDs. Tutorials are
always marked non-normative.

The canonical field spine is maintained in `TRACKS.md`; paths and hyperlinks
support navigation but do not replace artifact-version trace records.

## Impact and migration

Active links, the baseline manifest, architecture, project plan, workstream
ownership, evidence-manifest contract, publication/tutorial indexes, review
checklist, and repository validator are updated. The methodology mathematics and
verdict semantics do not change. The two external tutorial/planning notes remain
untracked local research inputs; none of their claims or prose is promoted by
this CR.

## Alternatives considered

1. Require complete independence — rejected because research requires
   engineering evidence, engineering implements method semantics, and tutorials
   explain both.
2. Keep the existing paths and add prose disclaimers — rejected because
   `docs/study/` and W7 still encode conflicting ownership.
3. Move all code, research, publication, and tutorials under one new mega-root —
   rejected because conventional code/test and thesis workspaces already provide
   useful physical separation; explicit contracts solve the actual problem with
   less migration risk.

## Required verification

- No active or required artifact remains under `docs/study/`.
- All active links resolve after the methodology-directory migration.
- Workstream ownership separates methodology, engineering, publication, common
  tutorial, and ARINC 615A tutorial outputs.
- Architecture and tutorial indexes contain the required version/trace fields.
- New and changed controlled documents pass English/Chinese structural checks
  and independent semantic review.
- The repository validator, test suite, and `git diff --check` pass.

## Approval disposition

DD-013 is accepted by `GR-PR6-RB-2026-001-v4.2`. The Evidence Manifest v1.2
provenance gap found during review was closed in
`fc847be7690e2f8fc7dc3a4c64056051a745ece4`. Migration requires downstream
research/publication and executable tutorials to consume stable manifest,
artifact/version, baseline/tool, and gate identifiers; paths or “latest” state
cannot substitute for them. Feedback that changes an upstream contract must use
CR/DD and Review control. This approval is effective only when PR #6 is merged
and its final-head CI/final-diff conditions are satisfied.

## 触发问题

仓库已经在物理上分开源代码、研究控制、出版和教程，但仍有三处歧义：`docs/study/` 混合权威方法与学习材料语义；W7 把该路径分配给教程工作流；出版和教程虽然具有不同证据责任和发布生命周期，却共享所有权。仅分目录不能阻止研究叙述依赖工程内部结构，也不能阻止教程意外成为规范来源。

## 决定

以下路径记录批准时的 v4.2 实现。CR-2026-003 随后迁移这些路径，但保持产品领域依赖规则不变。

- 把权威报告和索引迁移至 `docs/methodology/`。
- 把方法论研究/出版、工程实现和验证教程视为不同产品领域。
- 以治理和受控需求作为共享契约层。
- 分开出版与教程所有权，并把教程分为 `tutorial/common/` 和 `tutorial/arinc615a/`。
- 每个跨领域依赖必须标明上游产物 ID、版本和适用门禁记录。
- 下游证据只能通过 CR/DD 与评审控制反馈，不得直接反向依赖可变产物。

## 接口与追踪契约

方法论导出术语、模型/迹语义、判定规则、证据 schema 和门禁准则。工程导入这些契约，并导出版本化工具/配置/环境元数据与不可变证据清单。研究和出版消费清单，导出已注册分析和受门禁约束的主张。教程消费具名基线；可执行时还要消费具名工具发布及稳定示例/证据 ID。教程始终标记为非规范性。

权威字段脊柱位于 `TRACKS.md`；路径和超链接用于导航，但不能代替产物版本追踪记录。

## 影响与迁移

更新活动链接、基线清单、架构、项目计划、工作流所有权、证据清单契约、出版/教程索引、评审清单和仓库验证器。方法论数学和判定语义不变。两份外部教程/计划笔记继续作为未跟踪的本地研究输入；本 CR 不晋级其中任何主张或原文。

## 已考虑备选方案

1. 要求完全独立——不采用，因为研究需要工程证据，工程实现方法语义，教程解释二者。
2. 保留原路径并增加免责声明——不采用，因为 `docs/study/` 与 W7 仍编码冲突所有权。
3. 把代码、研究、出版和教程全部迁入一个新总目录——不采用，因为惯用代码/测试和论文工作区已经提供有用的物理分离，显式契约能以更低迁移风险解决实际问题。

## 必需验证

- `docs/study/` 下不再有活动或必需产物。
- 方法论目录迁移后全部活动链接可解析。
- 工作流所有权分开方法论、工程、出版、通用教程和 ARINC 615A 教程输出。
- 架构与教程索引包含必需版本/追踪字段。
- 新增和变化的受控文档通过中英文结构检查及独立语义评审。
- 仓库验证器、测试套件和 `git diff --check` 通过。
