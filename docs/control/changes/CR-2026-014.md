## Why this change exists

Three consistent deliveries on one Draft PR:

1. **F-A — derived inventory.** The README status block is generated from
   `project-status.json` free text, so a hand-written count can drift from the
   authoritative CRS while overview synchronization still passes. The status
   surface must derive the current CRS inventory from the controlled package,
   not from a second hand-filled copy.
2. **F-B — persisted regression.** The approved source-disposition boundaries
   for the PDF-30 adjacent CRC clauses must be protected by committed negative
   and positive tests that exercise the production checker, not only by an
   in-review ad-hoc mutation.
3. **F-C — algorithm presentation.** The top-level CL-TAV algorithm must be
   readable as a loop, with the prediction, interpretation and outcome-resolution
   duties carried by named sub-algorithms and a contract appendix. This is a
   presentation refactor of already-approved semantics.

## Presentation correction (review round R36)

The first presentation split is corrected. The main text now carries the top
level and the three core mechanisms — test selection and admission
(`ALG-CLTAV-05`), timed observation interpretation (`ALG-CLTAV-06`) and
history-compatible update (`ALG-CLTAV-07`) — while the appendix carries the
S2/S6/S7–S8 coordination wrappers (`ALG-CLTAV-02/03/04`), the typed records, the
responsibility map and the unresolved-kernel register. Interfaces use explicit
typed records with tagged alternatives and field access or destructuring: the
backend prediction gap is branched on before projection; the frozen select
snapshot is constructed and passed to interpretation and resolution; the
normalized resolution outcome and stop reason return to the caller. The production
checker uses a bounded executable-call model (comment-stripping, signature and
return-branch checks) that rejects the reviewed TeX mutations. This closes
R36-F01, R36-F02 and R36-F03 and addresses R36-A01; it does not change DD-029
semantics, return sets, error types or stop priority, and it does not reopen
F-A/F-B.

## 为何存在

同一 Draft PR 上的三项一致交付：

1. **F-A——派生清单。** README 状态块由 `project-status.json` 自由文本生成，因此手写计数

   份手填副本。
2. **F-B——持久化回归。** PDF 30 邻接 CRC 条款的已批准来源处置边界必须由提交的负例与正例

3. **F-C——算法呈现。** CL-TAV 总体算法必须可读为一个循环，预测、解释与结果处置职责由具名
   子算法与一个契约附录承载。这是对已批准语义的呈现重构。
