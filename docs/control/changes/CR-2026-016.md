## Objective and scope

Define the first offline UPLOAD/INFORMATION implementation slice: captured records, reconstruction, protocol-event identity, ownership, observation interpretation, bounded history compatibility, and traceable reporting.  The authoritative development package makes each bound CRS requirement exactly one explicit development disposition and connects first-slice obligations to modules and synthetic acceptance cases.

The candidate also fixes a finite explicit-path kernel contract, all eight algorithm and seven experiment interface bindings, and concrete positive/negative specification witnesses. Six CRC-bearing first-slice obligations are specification-closed while runtime integrity remains `NOT-ESTABLISHED`; missing implementation, configuration, execution or gate evidence yields `NOT-EVALUATED`, never a protocol verdict.

It also registers the 23 locally inspected captures as **exploratory development inputs**.  Captures and payloads remain outside the repository.  File annotation is not wire outcome; wire outcome is not independent case conclusion; neither is experimental truth.

## Boundaries

- No codec, protocol engine, solver, network I/O, IUT, injection, controlled execution, confirmatory result, Configuration, M3, tag, or baseline is created.
- The only CRS exception is the source-bound correction of the six authorized initialization/status files recorded by this CR: Protocol Version is two ASCII characters in LCI/LCL/LCS/LUR/LUS, and LUI reuses the initialization-field table. M2 is re-pinned to the corrected ancestor snapshot without changing transitions, timing, migration, selected services, or approval state. Accepted CL-TAV semantics, `src/`, and source-audit semantics otherwise remain unchanged.
- Unknown topology, clock accuracy, configuration, device version and root cause are explicit UNKNOWN values; they are not silently inferred from captures or used as algorithm priors.
- A first-slice readiness specification is not a protocol conformance claim, capability establishment, or confirmation of experimental adequacy.

## 目标与范围

定义首轮离线 UPLOAD／INFORMATION 实现切片：捕获记录、重建、协议事件身份、所有权、观测解释、有界历史相容更新和可追踪报告。权威开发包使每个绑定 CRS 需求恰有一个明确的开发处置，并把首轮义务关联至模块和合成验收案例。

候选还固定有限显式路径内核合同、全部八个算法接口和七个实验接口绑定，以及具体正负规格见证。六项带 CRC 的首轮义务在规格侧关闭，但运行完整性仍为 `NOT-ESTABLISHED`；缺少实现、配置、执行或门禁证据时产生 `NOT-EVALUATED`，绝不产生协议判定。

同时登记已在本地查看的 23 份捕获作为**探索性开发输入**。捕获与载荷不进入仓库。文件注释不等于线上结果；线上结果不等于独立案例结论；二者都不等于实验真值。

## 边界

- 不创建编解码器、协议引擎、求解器、网络 I/O、IUT、注入、受控执行、确认性结果、Configuration、M3、tag 或 baseline。
- CRS 的唯一例外是本 CR 记录的六个已授权初始化／状态文件来源修正：LCI／LCL／LCS／LUR／LUS 的 Protocol Version 为两个 ASCII 字符，LUI 复用初始化字段表。M2 重新钉到修正后的祖先快照，但不改变迁移、时序、服务选择或批准状态。除此之外，已接受 CL-TAV 语义、`src/` 与来源审计语义保持不变。
- 未知拓扑、时钟精度、配置、设备版本和根因均为显式 UNKNOWN；不得从捕获静默推断，亦不得用作算法先验。
- 首轮就绪规格不是协议符合性主张、能力建立或实验充分性确认。
