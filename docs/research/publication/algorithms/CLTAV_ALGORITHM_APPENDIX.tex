The short wrapper procedures below are the only places the interface macros are
invoked. They add no semantics beyond DD-029 / DD-033.

\begin{algorithm}[ht]
\caption{Select and admit (contract for ALG-CLTAV-01 S3)}
\label{alg:cltav-select}
\SetKwInput{KwIn}{Require}
\SetKwInput{KwOut}{Ensure}
\KwIn{$\Gamma$; $\eta$; current $H$; action library; predicted classes $\mathcal{C}$}
\KwOut{kind; final $t^\star$; selectable $S$; an Admit A2--A5 exit}
$A\leftarrow$ currently enabled actions\;
$(\textit{kind},t^\star,S,\textit{admit})\leftarrow$ \IFsel$(A,\Gamma.\mathrm{currentSummary},\mathcal{C},\Gamma,\eta,H)$\;
\uIf{$\textit{kind}=\mathrm{ADMIT}$}{\Return the Admit A2--A5 exit\;}
\uElseIf{$\textit{kind}=\mathrm{TEST}$}{
  \lIf{$S=\emptyset$}{\Return a named spec error; never $\arg\min$ an empty $S$\;}
  \tcp{$t^\star$ is the final one-step minimax action on currently valid nonempty classes inside TEST-only $S$}
}
\uElseIf{$\textit{kind}\in\{\mathrm{PREP},\mathrm{RECOVER}\}$}{keep the Prep or Recover $t^\star$ named by \IFsel; do not enter TEST minimax\;}
\Return $\textit{kind},t^\star$\;
\end{algorithm}

\begin{algorithm}[ht]
\caption{Execute and record (contract for ALG-CLTAV-01 S5)}
\label{alg:cltav-execute}
$(\textit{record},\textit{effect})\leftarrow$ \IFexec$(\Gamma,\textit{actionId})$; only the admitted action is issued once\;
\Return $\textit{record},\textit{effect}$\;
\end{algorithm}

\begin{algorithm}[ht]
\caption{Stop gate (contract for ALG-CLTAV-01 S1 and S10)}
\label{alg:cltav-stop}
\SetKwInput{KwIn}{Require}
\SetKwInput{KwOut}{Ensure}
\KwIn{$\Gamma$; $H$; $\eta$; named 645 residuals; equivalence status}
\KwOut{an exclusive stop class, or \emph{undecided}}
$\sigma\leftarrow$ first of Stop-Empty, Stop-Singleton, Stop-645, Stop-Equivalent, Stop-Budget via \IFres$(\Gamma,H,\eta)$ and \IFeq$(\Gamma,H,\eta)$\;
\lIf{$\sigma$ is set}{\Return $\sigma$}
\Return \emph{undecided}; a currently non-distinguishing $H$ is not proved equivalent\;
\end{algorithm}

\section*{Appendix C. Unresolved computation kernels}
\label{app:cltav-kernels}

Control logic, call order, state reads/writes, budget, return values and error
branches are fully specified above. The internal solution techniques remain open
and are abstracted by named contracts; no probability default, HMM/DTMC/Bayesian
kernel or continuous-time discrete grid is introduced here.
