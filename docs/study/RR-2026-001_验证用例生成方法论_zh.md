## 摘要

航空电子数据加载领域的协议符合性验证长期停留在项目级 ICD 测试层面，缺乏系统化方法来证明协议层面的标准符合性。本报告提出一种面向 ARINC 615A 数据加载协议的**符合性验证方法论**，包含两种互补的验证方法（对应 DO-178C §6.4）：**基于需求的测试**（§4–5）与**概率置信分析**（§6）。

测试组件整合五大已有理论支柱：(1) ISO/IEC 9646 符合性测试导出链；(2) ETSI 测试目的形式化；(3) 基于有限状态机的覆盖准则（W/Wp/HSI 方法）；(4) ioco 符合性理论；(5) 基于变异测试的充分性验证。我们提出五阶段导出流程——需求提取、测试目的导出、验证用例规格化、覆盖性验证、充分性证明——并以六个形式化定义加以刻画。方法以 ARINC 615A 数据加载协议为实例化对象，设计基础/扩展 VCS 分离结构（对应 ISO 9646 符合性类）。通过结构化保证论证（assurance argument），证明在给定故障模型范围内，通过全部基础验证用例即构成高置信度符合性证据。

分析组件引入基于分层离散时间马尔科夫链（DTMC）和隐马尔科夫模型（HMM）的概率符合性置信度模型。转移矩阵元素解释为*验证置信度*（贝叶斯认知度量），而非 IUT 内在行为概率。每个协议层（UDP、TFTP、615A、665、664）建模为独立子状态机，带角色标记和块类型分段。参数从自环验证数据和变异测试结果中保守估计，避免未经验证的独立性假设。框架进一步集成 FMEA/FMEDA 用于失效模式分析，并通过 Viterbi 算法实现验证失败时的故障定位。

创新点不在于任何单一技术，而在于将已有技术系统集成为一个可迁移、可审计的验证方法论——将基于需求的测试与概率置信分析相结合——用于数据加载协议符合性验证。

**关键词：** 协议符合性验证；基于需求的测试；概率置信分析；验证用例导出；需求覆盖；ARINC 615A；变异测试；ISO/IEC 9646；DO-178C；马尔科夫链；隐马尔科夫模型；验证置信度；FMEA；故障定位

## 1. 引言

### 1.1 问题背景

民用航空电子系统依赖标准化数据加载协议（ARINC 615A，基于 TFTP/UDP/以太网）向可更换单元（LRU）传输软件和配置数据。当前验证实践通常在**项目 ICD 层面**进行——测试特定机型的接口行为——而缺乏系统化方法来证明针对 ARINC 615A 标准本身的**协议级符合性**。

### 1.2 研究空白

现有文献中不存在一种项目无关的方法能够：
- 从 ARINC 615A 规范性需求系统导出完整的验证用例集
- 提供将需求覆盖与符合性证据相关联的形式化覆盖论证
- 通过基于变异的充分性证明来验证检测能力
- 将基础符合性（标准导出、稳定）与扩展测试（项目特定）分离

### 1.3 研究问题

> **RQ：** 如何设计一种项目无关的方法论，从协议需求规格系统化生成验证用例集（VCS），使得：
> 1. **覆盖完备性**——基础需求集中的每一条符合性需求至少被一个验证用例覆盖；
> 2. **符合性证明**——通过全部基础 VCS 即构成协议符合性的充分证据；
> 3. **检测能力**——VCS 能够检测不符合性（通过变异/故障注入验证）；
> 4. **可扩展性**——可添加项目特定扩展 VCS 而不损害基础符合性证明？

### 1.4 子问题

| 编号 | 子问题 |
|------|--------|
| SQ1 | 何种形式化导出链将标准条款映射为：符合性需求 → 测试目的 → 验证用例？ |
| SQ2 | 何种覆盖准则对协议符合性是必要且充分的？ |
| SQ3 | "覆盖完备蕴含符合性"这一论断如何形式化论证？ |
| SQ4 | 基础/扩展分离与 ISO 9646 符合性类之间的关系是什么？ |

### 1.5 范围

- **范围内：** 方法论与理论；ARINC 615A DOWNLOAD/UPLOAD（基于 TFTP）；基础 + 扩展 VCS 设计
- **范围外：** 软件实现细节；FIND/INFORMATION 服务；完整 ARINC 665 编解码验证

## 2. 理论基础

### 2.1 ISO/IEC 9646 符合性测试方法论

ISO/IEC 9646 (1994) 定义了协议符合性测试的经典方法论：

| 概念 | 定义 | 与本方法的关联 |
|------|------|----------------|
| 符合性需求 | 标准中 IUT 必须满足的需求 | 从 ARINC 615A 条款导出 |
| 测试目的 | 对测试验证何种符合性方面的聚焦描述 | 与 VC 为 1:1 或 1:N 映射 |
| 抽象测试套件 (ATS) | 覆盖全部符合性需求的抽象测试用例完整集 | 即本方法的"基础 VCS" |
| PICS | 实现支持哪些选项/特性的声明 | 确定适用子集 |
| 符合性类 | 按能力级别分组的需求集 | 基础/扩展分离 |
| 测试导出 | 标准 → 需求 → 测试目的 → 抽象测试用例 → 可执行测试 | 本方法的导出链 |

**核心原则：** "符合性测试并非穷尽性的；通过测试套件不意味着 100% 的符合性保证。但它确实以高置信度确保 IUT 符合指定需求"（ISO/IEC 9646-1, §1）。

### 2.2 ETSI 测试规格方法 (TR 102 840)

ETSI TR 102 840 提供了操作性导出流程：

```
标准/规格说明
  → 识别符合性需求
    → 制定测试目的（每个需求或需求组一个）
      → 导出抽象测试用例（前置条件 + 激励 + 期望行为）
        → 实现可执行测试用例（TTCN-3）
```

**覆盖规则：** 每条符合性需求至少被一个测试目的覆盖；每个测试目的至少被一个测试用例实现。这构成从测试用例到需求的**满射映射**。

### 2.3 协议规格形式化模型

| 模型 | 优势 | 局限 | 适用性 |
|------|------|------|--------|
| FSM | 简单；W/Wp/HSI 保证转移覆盖 | 状态爆炸；无数据处理 | 经典协议 |
| EFSM | 变量、守卫、动作 | 不可判定性；生成困难 | 工业协议 |
| LTS | ioco 理论基础；处理非确定性 | 无数据；无限状态复杂 | 形式符合性 |
| CEFSM | 分布式协议 | 组合复杂性 | OSI、电信 |
| Petri 网 | 并发、同步 | 测试生成不成熟 | 并行协议 |
| UML 状态图 | 工业标准；层次化 | 语义间隙 | MBSE、DO-178C |

**对 ARINC 615A：** 协议为基于会话的状态机（IDLE → SETUP → TRANSFER → COMPLETE/ERROR），含数据参数。**EFSM 模型**最为适用。

### 2.4 ioco 符合性理论 (Tretmans, 1996)

输入/输出符合性关系提供形式化基础：

- 规格 S 为标记迁移系统
- 实现 I 为输入输出迁移系统
- **I ioco S** 当且仅当：对 S 的每条迹 σ，outputs(I, σ) ⊆ outputs(S, σ)

验证用例本质上是**采样测试迹**，检验 IUT 响应是否保持在规格允许的行为范围内。"全部 VC 通过"是完整 ioco 符合性的采样近似。

### 2.5 基于 FSM 的测试生成方法

| 方法 | 覆盖保证 | 参考文献 |
|------|----------|----------|
| W-方法 | 检测输出故障 + 转移故障（k 个额外状态内） | Chow (1978) |
| Wp-方法 | 同等保证，更小套件 | Fujiwara et al. (1991) |
| HSI-方法 | 协调状态标识 | Luo et al. (1994) |
| H-方法 | 通过协调迹改进 | Dorofeeva et al. (2003) |
| 基于变异 | 杀死故障模型中所有非等价变异体 | Petrenko (2016) |

**核心洞察：** "测试套件 T 对故障模型 F 完备，当且仅当对 F 中每个非等价变异体 M，存在 t ∈ T 能区分规格与 M"（Bochmann, 1991; Petrenko, 2016）。

本方法采用**需求驱动**方式（非纯 FSM 遍历），因为 ARINC 615A 以自然语言 + 表格规格化，且需求覆盖可审计。完备性通过变异/故障注入**验证**。

### 2.6 理论基础 → 方法映射

§2.1–2.5 的五大理论支柱分别支撑测试方法论（§4–5）的特定阶段。分析组件（§6）引入独立于 §2 的数学工具。

| 理论支柱 | 支撑阶段 | 角色 |
|----------|----------|------|
| ISO/IEC 9646 (§2.1) | §4.1–4.7（完整流水线） | 导出链：标准 → CRS → TP → ATS → 可执行；符合性类 → 基础/扩展分离 |
| ETSI TR 102 840 (§2.2) | §4.2–4.4 | 满射映射规则（每条需求 ≥ 1 个测试目的）；操作性导出流程 |
| EFSM 模型 (§2.3) | §4.5（覆盖 L2/L3） | 状态/转移覆盖准则；同时为 §6 分层状态机提供建模语言 |
| ioco 理论 (§2.4) | §5（形式化论证） | VC 作为采样测试迹近似 ioco 符合性；定义 5 的理论锚点 |
| FSM 变异测试 (§2.5) | §4.6（充分性证明） | W/Wp/HSI 转移覆盖保证；变异充分性作为有限故障模型界 |

**核心观察：** §2 全部内容支撑**测试**组件（§4–5）。**分析**组件（§6）引入独立的数学工具箱（DTMC、HMM、贝叶斯估计、FMEA/FMEDA），不源自 §2。两个组件是 DO-178C §6.4 下的互补验证方法（见 §5.5）。

## 3. 相关工作

### 3.1 基于需求的测试生成 (RBTG)

Yang et al. (2025) 综述 267 篇 RBTG 论文。主要发现：
- 需求分类：自然语言 → 半形式化 → 基于模型 → 形式化数学 → 混合
- 生成方法：基于规则、模型检测、搜索式、NLP/LLM 式
- 覆盖准则：需求覆盖、场景覆盖、状态/转移覆盖、数据流覆盖
- **空白：** RBTG 聚焦软件需求；协议符合性需求（规范性 "shall" 条款）代表性不足

### 3.2 协议符合性测试

| 工作 | 方法 | 关联 |
|------|------|------|
| ISO/IEC 9646 (1994) | 需求 → 测试目的 → ATS | 直接前身 |
| ETSI TTCN-3 套件 | 可执行符合性测试 | 操作模板 |
| Schieferdecker (2000) | 基于 TTCN 的形式化导出 | TP → TC 映射 |
| Dssouli et al. (1999) | 基于 FSM，完全故障覆盖 | 故障模型方法 |
| Petrenko (2016) | SMT 求解 + 变异体杀死 | 形式完备性 |
| Li et al. (2021) | 基于模型的测试 (StateAFL) | 模糊测试 + 状态模型 |

### 3.3 航空电子验证标准

| 标准 | 关联 |
|------|------|
| DO-178C (RTCA, 2011) | 所有 DAL 级别要求基于需求的测试 |
| DO-330 (RTCA, 2011) | 认证中的工具鉴定 |
| ARINC 615A (SAE) | 被测协议 |
| ARINC 665 (SAE) | LSAP 文件结构 |
| ARINC 664 (SAE) | AFDX/LU 数据格式 |

DO-178C §6.4.4.2 要求基于需求的测试——本方法类似但应用于协议符合性层面。

### 3.4 变异测试与充分性

测试套件 T 为**变异充分**的，当且仅当杀死所有非等价变异体。关键文献：DeMillo et al. (1978)、Jia & Harman (2011)、Petrenko (2016)、Nicourt et al. (2024)。

### 3.5 符合性类（基础/扩展分离）

类似结构：PROFINET CC-A/B/C、ODVA 符合性 + 互操作性、3GPP 基础 + 配置文件特定。本方法的基础/扩展模型对应 ISO 9646 符合性类层次，具有形式化无干扰性质。

## 4. 所提方法

### 4.1 五阶段导出

```
阶段 1：需求提取
  标准文本 → 符合性需求集 (CRS)

阶段 2：测试目的导出
  CRS → 测试目的集 (TPS) [满射映射]

阶段 3：验证用例规格化
  TPS → 抽象验证用例集 (AVCS)

阶段 4：覆盖性验证
  AVCS × CRS → 覆盖矩阵 [验证满射性]

阶段 5：充分性证明
  变异/故障注入 → 检测能力证据
```

### 4.2 阶段 1：需求提取

**输入：** ARINC 615A 规范性条款  
**流程：**
1. 识别所有规范性陈述（含 "shall"、"must"、"is required to"）
2. 分类：功能性 / 数据 / 时序 / 错误处理 / 会话
3. 分配唯一标识（如 `REQ-615A-DL-001`）
4. 记录标准引用（条款号、页码）

**输出：** CRS = {r₁, r₂, ..., rₙ}

### 4.3 阶段 2：测试目的导出

每条 rᵢ 必须被 ≥1 个测试目的 tpⱼ 覆盖。导出启发式：
1. **正向：** 验证需求规定的正确行为
2. **反向：** 验证违规时的错误处理
3. **边界：** 验证极限处行为（如最大块大小）

映射：CRS → TPS 为满射；一条需求可产生多个 TP (1:N)。

### 4.4 阶段 3：验证用例规格化

每个 TP 细化为 ≥1 个抽象验证用例，模式包含：
- VC-ID、标题、功能分配（DLS/THW）、优先级
- 前置条件、激励/步骤、期望结果、判定准则
- 测试目的引用、需求引用、标准引用
- 验证状态、审批状态

### 4.5 阶段 4：覆盖性验证

**层次化覆盖准则：**

| 级别 | 准则 | 必要性 |
|------|------|--------|
| L1 | 需求覆盖（∀r ∈ CRS, ∃VC） | 强制 |
| L2 | 状态覆盖（所有协议状态被访问） | 强制 |
| L3 | 转移覆盖（所有转移被执行） | 强制 |
| L4 | 数据流覆盖（字段在边界值测试） | 推荐 |
| L5 | 反向覆盖（错误条件被触发） | 推荐 |
| L6 | 序列覆盖（端到端场景） | 可选 |

L1+L2+L3 = 最低符合性证明；L4+L5 = 加强证明；L6 = 系统级置信。

### 4.6 阶段 5：充分性证明

**故障模型类别：** 报文格式 / 状态转移 / 时序 / 数据完整性 / 会话 / 选项处理

**流程：** 生成变异体 → 执行基础 VCS → 计算变异分数  
**充分性声明：** 分数 = 1.0 → VCS 能检测模型中所有故障

### 4.7 基础/扩展分离

| 层 | 来源 | 目的 | 稳定性 |
|----|------|------|--------|
| 基础 VCS | ARINC 615A 标准 | 证明符合性 | 稳定 |
| 扩展 VCS | 项目 ICD | 项目特定保证 | 随项目变化 |

扩展 VC 为附加性质；不修改或否定基础证明。

### 4.8 人工介入与自动化

| 阶段 | 人工介入 | 可自动化 | 可半自动化 |
|------|----------|----------|------------|
| §4.2 需求提取 | 解释规范性条款；分类（功能/数据/时序/错误/会话）；判断 "shall" 范围 | ID 分配；标准引用记录；格式化 | — |
| §4.3 测试目的导出 | 从需求导出 TP（领域知识）；判断正向/反向/边界充分性 | — | 基于模板的 TP 导出（正向/反向/边界启发式）；需人工审查 |
| §4.4 VC 规格化 | 设计前置条件、激励、期望结果、判定准则（协议专业知识） | 模式格式化；ID 生成；交叉引用；YAML→Excel 导出 | 基于模板的 VC 草稿（从 TP）；定稿前人工审查 |
| §4.5 覆盖性验证 | 解释覆盖缺口；决定缺口是否可接受 | 覆盖矩阵构建；满射性检查；L1–L6 指标计算；缺口报告 | — |
| §4.6 充分性证明 | 设计故障模型（协议知识）；解释存活变异体 | 变异体生成（给定故障模型）；变异体执行；变异分数计算 | 变异体优先级排序 |

**规律：** 越接近规格说明解释的阶段（1–3）需要越多人工专业知识；越接近执行和计算的阶段（4–5）自动化程度越高。分析组件（§6）在执行层面完全可自动化（状态跟踪、参数估计、置信度计算、Viterbi 定位），但状态机设计和结果解释需要人工判断。

## 5. 形式化论证

### 5.1 保证论证结构

```
声明：IUT 符合 ARINC 615A 规格说明

├── 论证 1：需求覆盖
│   └── 覆盖矩阵证明满射映射
├── 论证 2：行为覆盖
│   └── 所有状态 + 转移被执行
├── 论证 3：检测能力
│   └── 变异验证杀死所有非等价变异体
└── 论证 4：范围边界
    └── 明确非目标；置信度相对于故障模型
```

### 5.2 形式化定义

**定义 1 (CRS)：** CRS(S) = {r | r 是标准 S 中的规范性需求}  
**定义 2 (VC)：** vc = (id, pre, stimulus, expected, verdict, ref)，ref ∈ CRS(S)  
**定义 3 (VCS)：** VCS = {vc₁, ..., vcₘ}  
**定义 4 (覆盖)：** VCS 覆盖 CRS(S) 当且仅当 ∀r ∈ CRS(S), ∃vc ∈ VCS : vc.ref = r  
**定义 5 (符合性证据)：** 在所假定的符合性需求集 CRS(S) 与故障模型 F 之下，若 VCS 覆盖 CRS(S) 且全部验证用例判定均为 PASS，则构成**在 CRS(S) 与 F 范围内主张协议符合性的充分证据**——而非对一切可能行为、或对 F 之外故障的无限制证明。
**定义 6 (充分性)：** VCS 对 F 充分当且仅当 ∀m ∈ (F \ 等价体), ∃vc ∈ VCS : vc 杀死 m

### 5.3 局限性

1. 非穷尽性（输入空间无限）
2. 依赖故障模型（保证受模型约束）
3. 依赖规格说明（歧义影响解释）
4. 时序局限（时序符合性需专门测量）

### 5.5 验证方法分类（测试 vs. 分析）

DO-178C §6.4 定义四种验证方法：测试、分析、审查、演示。本方法论采用其中两种：

| DO-178C 方法 | 本方法论 | 范围 |
|----------------|----------|------|
| **测试** | §4–5：基于需求的测试 | 生成 VC → 对 IUT 执行 → 通过/失败判定 → 覆盖验证 → 变异充分性 |
| **分析** | §6：概率置信分析 | 从测试证据量化置信度 → FMEA/FMEDA 诊断 → Viterbi 故障定位 |
| 审查 | 不在范围内 | 代码/设计检查 |
| 演示 | 不在范围内 | 无详细测量的功能观察 |

**关系：** 测试与分析是**互补而非顺序**的。测试产生证据（判定、迹）；分析解释该证据（置信度指标、故障诊断）。分析不产生新的测试执行——它评估已有结果。

```
              符合性验证
              ╱                       ╲
    测试 (§4–5)              分析 (§6)
         │                            │
   执行 VC → 判定          量化置信度 → 诊断
         │                            │
         └────── 证据 ────────────┘
              ╲                       ╱
           符合性声明
        （限定于 CRS + F）
```

**对文档标题的影响：** 本方法论不仅仅是“验证用例生成”（仅覆盖 §4），而是包含测试与分析的完整验证方法论。

## 6. 概率扩展：量化符合性置信度建模

### 6.1 语义基础

**约束性决定：** 转移矩阵元素 P(sᵢ, sⱼ) 代表“验证置信度”——即给定实验证据后，我们对 IUT 正确执行转移 (sᵢ → sⱼ) 的贝叶斯认知度量。它不代表 IUT 的内在行为概率。

**不确定性边界：**
- **确定的（模型侧）：** 状态集 S、合法转移拓扑、覆盖准则、判定规则
- **不确定的（IUT 侧）：** IUT 在各测试点是否真正符合——量化为认知概率

此解释避免了对 IUT 随机性的本体论承诺，同时允许严格的统计推断。

### 6.2 协议时序流程与状态枚举

ARINC 615A 协议栈按层建模。TFTP 层（代表性示例）的完整状态集：

| 状态 | 名称 | 自环？ | 描述 |
|------|------|--------|------|
| S0 | IDLE | — | 无活动会话 |
| S1 | WAIT_OACK | 是（重试） | 请求已发送，等待协商响应 |
| S2 | WAIT_ACK0 | 否（瞬态） | OACK 已收到，ACK(0) 已发送 |
| S3_first | XFER_FIRST | 是 | 首块 DATA(1) 传输 |
| S3_mid | XFER_MID | 是（核心） | 中间块 DATA(2..65534) |
| S3_last | XFER_LAST | 否 | 末块（len < blksize） |
| S3_roll | XFER_ROLLOVER | 是 | 块编号回卷 (65535→1) |
| S3'_first | RETX_FIRST | 是（有界） | 首块重传 |
| S3'_mid | RETX_MID | 是（有界） | 中间块重传 |
| S4 | XFER_RECV | 是（核心） | 接收 DATA，发送 ACK (UPLOAD) |
| S4' | XFER_DUP | 是 | 重复 DATA 处理 |
| S5 | COMPLETE | — | 传输成功结束 |
| S6 | ERROR_LOCAL | — | 本地错误（超时耗尽、序列错误） |
| S7 | ERROR_REMOTE | — | 收到远端 ERROR |
| S8 | ERROR_TID | 是 | 收到未知 TID 报文 |

**块分段规则：** 块传输状态分为四类（首块/中间块/末块/回卷块）——非单一状态，非 65535 状态穷举。

**回卷处理：** S3_roll 在 S3_mid 内计数器 c = 65535 时触发。建模为扩展状态 (S3_mid, c)，马尔科夫性在扩展状态空间上成立。

### 6.3 分层 DTMC 架构

**本修订（PR #2）中 DTMC 的定位：** 分层 DTMC **保留为解释性模型（interpretation model）**——用于叙述协议阶段，并沿合法转移组织认识置信标签。此处**不**将其宣称为符合性证明的唯一、最终数学基础（证明基础仍为定义 1–6 + 覆盖 + 变异充分性）。进一步抽象（例如 Protocol Evidence Graph / 不要求随机核的带标签迁移图）记为 **理论债务，留待 PR #4**。

**设计原则：**
1. 每个协议层（UDP、TFTP、615A、665、664）拥有独立子状态机
2. 统一链 + 角色标记（DLS/THW）——一个模型，两个角色视角
3. 重传状态独立于正常传输状态
4. 层间耦合：上层将下层视为原子操作（成功/失败）

**层间马尔科夫性：**
- 各层内部：DTMC 成立
- 层间：半马尔科夫（逻辑马尔科夫，时间非马尔科夫）
- 对验证置信度：建模逻辑正确性，非时间分布 → 每层 DTMC 即可

### 6.4 参数估计（保守、数据驱动）

**数据来源：** 自环验证（同状态重复测试）+ 变异测试（故障注入结果）。

**自环 i.i.d. 范围：** 仅同一状态上的自环采样为 i.i.d。跨状态依赖由马尔科夫链结构建模，不假设全局独立。

| 场景 | 方法 | 理由 |
|------|------|------|
| 数据充分 (n ≥ 30) | 频率估计 θ̂ = c/n | 无需先验 |
| 数据稀疏 (n < 10) | Jeffreys 先验 Beta(1/2, 1/2) | 无信息先验 |
| 未直接测试 | 标记“未验证” | 不赋概率 |
| 变异提供间接证据 | 下界约束 | 检测能力 ≥ 观测值 |

**置信区间（精确，无渐近假设）：** Clopper-Pearson 精确区间。

### 6.5 HMM 形式化

验证过程建模为隐马尔科夫模型。**隐状态、观测与参数不得混为一谈：**

| 概念 | 符号 | 角色 |
|------|------|------|
| **隐状态** | \(Z_k\) | 第 \(k\) 步不可观测的实现符合/故障类 |
| **观测** | \(X_k\) | 第 \(k\) 步测试裁决，\(X_k \in \{\mathrm{PASS},\mathrm{FAIL}\}\) |
| **参数** | \(\theta\) | 仅指模型参数：初值分布、转移核、发射核——**不是**隐状态本身 |

**示例隐状态字母表（可扩展）：**  
\(\{ \mathrm{Conforming},\ \mathrm{RetryFault},\ \mathrm{TimeoutFault},\ \mathrm{SequenceFault},\ \mathrm{FileIntegrityFault},\ \ldots \}\)。

**发射（示意，待标定）：**  
\(P(X_k=\mathrm{PASS}\mid Z_k=\mathrm{Conforming})=1-\alpha\)，  
\(P(X_k=\mathrm{PASS}\mid Z_k\neq\mathrm{Conforming})=\beta\)，  
其中 \(\alpha\) 为误判 FAIL 率，\(\beta\) 为漏检/逃逸率（可在有变异证据时取保守上界）。

**转移：** \(P(Z_{k+1}\mid Z_k)\) 是独立的隐动态核（故障持续/恢复假设），**不得**与 §6.6 中的认识置信标签等同；§6.3 的分层 DTMC 仍作为协议结构与置信叙述的**解释性模型**（进一步形式化见理论债务 → PR #4）。

**可用推断（在 \(\theta\) 固定后）：**
- **前向算法：** 观测序列在 HMM 下的似然
- **Viterbi 算法：** 失败时最可能隐状态路径 → 辅助故障定位
- **Baum-Welch (EM)：** 仅在数据充分且带保守约束时用于参数学习

### 6.6 置信度指标

**指标 1——最弱环节（保守下界）：**
\[
C_{\mathrm{protocol}} = \min_{\ell}\min_{s} \theta_{s}^{(\ell)}
\]
**理由（安全工程 / 保守保证）：** 该指标**故意取保守**。在安全工程与保证实践中，一串义务常以**最弱已验证环节**为界：任一关键已验证要素的认识置信偏低，则总体主张不应超过该下界。因此指标 1 是**保守保证度量（Conservative Assurance Metric）**，而非平均行为的估计。未验证要素（\(\theta=\bot\)）应从 \(\min\) 中排除，或使定量主张保持不完整（报告时须声明政策）。

**指标 2——沿验证证据图的路径置信（条件累积）：**
设关键验证路径诱导有序证据序列 \(v_0,v_1,\ldots,v_m\)（VC 访问的状态或转移检查）。路径置信沿该**证据图条件累积**，而非假定事件相互独立：
\[
C_{\mathrm{path}} = \prod_{i=1}^{m} P(v_i \mid v_{i-1})
\]
其中 \(P(v_i\mid v_{i-1})\) 表示在接受第 \(i-1\) 步之后，对第 \(i\) 步的认识置信（操作上由对应边/状态转移的估计置信标签实例化）。

**明确非声称：** **不**将 \(\{v_i\}\) 当作无条件独立的伯努利试验。禁止将无条件边缘量的朴素乘积 \(\prod \theta_i\)（缺少条件/证据图解读）用作符合性度量。

**指标 3——分层置信度向量：**
\[
C = (C_{\mathrm{UDP}}, C_{\mathrm{TFTP}}, C_{\mathrm{615A}}, C_{\mathrm{665}}, C_{\mathrm{664}})^{\mathsf{T}}
\]

报告方式：同时给出指标 1 与 2。指标 1 用于安全关键下界；指标 2 用于条件累积规则下的每操作路径置信。

### 6.7 FMEA/FMEDA 集成与故障定位

**每转移 FMEA：** 每个转移 (sᵢ → sⱼ) 关联失效模式、局部/全局影响、严重度 (S)、检测手段（VC 引用）、诊断覆盖率 (DC)。

**FMEDA 量化：** DC_i = 被 VC 检测的失效模式数 / 该转移全部失效模式数。变异分数用作诊断覆盖率 DC 的**经验估计量**（非数学恒等式）。

**FMEA ↔ 变异映射字典（模板）：**

| 转移 | 失效模式 ID | 失效模式 | 局部影响 | 全局影响 | 严重度 | 检测 VC | 变异算子 | 已检测？ |
|------|------------|----------|----------|----------|--------|---------|----------|----------|
| S1→S2 | FM-TFTP-01 | OACK 被忽略 | blksize 保持默认 | 大文件传输可能失败 | 中 | VC-TFTP-NEG-003 | 移除 OACK 处理 | 是 |
| S3_mid→S3_mid | FM-TFTP-02 | 块计数器未递增 | 发送重复 DATA | 接收方拒绝；传输停滞 | 高 | VC-TFTP-XFER-007 | 冻结 block_num | 是 |
| S3_roll→S3_first | FM-TFTP-03 | 回卷 65535→0 而非 →1 | 接收方序列错误 | 传输中止 | 高 | VC-TFTP-ROLL-001 | next_block 返回 0 | 是 |
| S3'_mid→S3_mid | FM-TFTP-04 | 重传块号错误 | 接收方序列错误 | 传输中止 | 高 | VC-TFTP-RETX-002 | 篡改重传 block_num | 是 |
| S4→S4' | FM-TFTP-05 | 重复 DATA 被追加 | 数据损坏 | 文件完整性失败 | 关键 | VC-TFTP-DUP-001 | 移除重复检查 | 是 |
| S1→S6 | FM-TFTP-06 | 超时未执行 | 无限挂起 | 会话永不完成 | 中 | VC-TFTP-TMO-001 | 设置 timeout=∞ | 是 |

*此表为模板；完整字典在 VC 开发过程中按协议层填充（见 PR #5 工程范围）。*

**失败时故障定位（Viterbi + FMEA）：**
1. 观测失败序列 X₁, ..., Xₖ, Xₖ₊₁ = FAIL
2. Viterbi 算法 → 最可能故障状态 s*
3. 查询 FMEA 表 → 按严重度排序失效模式
4. 输出：诊断报告（疑似失效模式 + 建议排查方向）

**闭环：** 建模 → 执行 VC → 通过：计算置信度 / 失败：Viterbi 定位 → FMEA 诊断 → 失效模式报告

### 6.9 假设与局限性（严格声明）

1. **自环 i.i.d.：** 仅在同状态重复验证时成立；不假设跨状态独立
2. **马尔科夫性：** 在完整状态编码下每层成立；回卷需扩展状态
3. **共因故障：** 通过共享组件分析 + 变异覆盖识别；残余风险已声明
4. **无未验证先验：** 仅对稀疏数据使用 Jeffreys 先验；从不使用主观先验
5. **模型确定性：** 协议规格是确定的；概率仅描述认知不确定性
6. **故障模型有界：** 检测保证仅在声明的故障模型内成立

### 6.10 数值玩具示例

**场景：** TFTP 层，状态 S3_mid（中间块传输），自环验证 n = 50 次重复执行。

**步骤 1——参数估计：**
- 观测：c = 48 PASS，2 FAIL，共 n = 50
- 频率估计：θ̂ = 48/50 = 0.96
- 95% Clopper-Pearson CI：θ ∈ [0.863, 0.995]
- Jeffreys 后验（若 n 较小）：Beta(48.5, 2.5)，后验均值 = 48.5/51 = 0.951

**步骤 2——最弱环节指标（指标 1）：**
假设完整 VCS 执行后各层最小置信度：

| 层 | min θ_s | 限制状态 |
|------|---------|----------|
| UDP | 0.99 | U1'（重传） |
| TFTP | 0.96 | S3_mid（中间块） |
| 615A | 0.98 | A3（传输活动） |
| 665 | 1.00 | —（全部通过） |
| 664 | 1.00 | —（全部通过） |

C_protocol = min(0.99, 0.96, 0.98, 1.00, 1.00) = **0.96**（受限于 TFTP S3_mid）

**步骤 3——路径置信度（指标 2）：**
关键 DOWNLOAD 路径：S0→S1→S2→S3_first→S3_mid→S3_last→S5

| 步骤 | 转移 | P(v_i \| v_{i-1}) |
|------|------|-------------------|
| 1 | S0→S1 | 0.99 |
| 2 | S1→S2 | 0.98 |
| 3 | S2→S3_first | 0.99 |
| 4 | S3_first→S3_mid | 0.97 |
| 5 | S3_mid→S3_last | 0.96 |
| 6 | S3_last→S5 | 0.99 |

C_path = 0.99 × 0.98 × 0.99 × 0.97 × 0.96 × 0.99 = **0.893**

**步骤 4——分层置信度向量（指标 3）：**
C = (0.99, 0.96, 0.98, 1.00, 1.00)ᵀ

**解释：**
- 指标 1 (0.96)：保守下界——“我们对最弱已验证元素至少有 96% 的置信”
- 指标 2 (0.893)：路径级置信——“在条件证据累积下，整条 DOWNLOAD 路径被正确实现的概率”
- 指标 3：识别 TFTP 为限制层；引导未来验证工作至 S3_mid 自环采样

**变异证据整合：**
若对 S3_mid 的变异测试得分 = 5/5（所有变异体被杀死），则提供证据表明 DC(S3_mid) ≥ 1.0（在声明的故障模型内），增强对 θ̂ = 0.96 的置信（2 次 FAIL 可能为环境因素，而非符合性失败）。

## 7. 定位与创新性

| 方面 | ISO 9646 | ETSI/TTCN | DO-178C | **本方法** |
|------|----------|-----------|---------|------------|
| 领域 | OSI 协议 | 电信 | 机载软件 | 数据加载协议 |

| 验证方法 | 仅测试 | 仅测试 | 测试 + 分析 + 审查 + 演示 | **测试 + 分析**（互补） |
